VR Personal Project

C++ and Unreal Engine 5

In my free time I enjoy lots of VR to the point that I enjoy implementing gameplay features that I saw in other games.

This VR personal project is a physics-based VR game featuring complex weapon interactions and immersive gameplay mechanics.

Technical Gameplay Details

The following features were developed entirely using C++. Blueprints were used mostly to setup and assign assets.

  • Grab Interaction System.
    • Allows to grab objects based on distance and angle.
    • Allows to define multiple grab points on an object.
    • Items can have inventory slots for ammo or attachments.
    • Items and weapons can be held and aimed with two hands.
    • Complex interactions like ammo can be placed inside a gun.
  • Weapon Shooting Bullet System.
    • Weapons use niagara effect to spawn a trail which disappears after a few seconds.
    • At the impact point, a decal is spawned.
    • Different spawned decals based on material type the bullet hits.
    • Items and weapons can be held and aimed with two hands.
  • Climbing system.
    • Grabbing with a hand on a wall locks hand and allows to move capsule.
    • Player can also fling itself using the wall which results in propelling capsule upwards.
  • Heavily physics based.
    • Player hands are physics based and can't be forced inside walls.
    • If player tries to push their head inside a wall, he is corrected and pushed away from it.
    • Held items and weapons can't be pushed inside walls.
  • Inventory Slot System.
    • Allows to define multiple inventory slots for an items or weapons.
    • Weapon use ammo slots that allow to store visible ammo and used when weapon is triggered.
    • Player has two inventory slots at his sides which allow him to store and retrieve one item in each.
  • Save/Persistence System.
    • Using Unreal's serialization system, it stores player inventory and items in the level.
    • Allows to save, load, delete game state at any given time.
    • Stores items and weapons in the level as well as in player inventory.
    • Makes use of the SaveGame blueprint tag to define which UPROPERTY should be saved.
    • Uses unique identifiers for each item to ensure that items are not duplicated when traveling to next level.
  • Travel System.
    • Allows player to initiate travels to other levels.
    • Travels follow a sequence:
      1. Black sphere slowly envelops player and camera and player is transported to loading level.
      2. At loading level player waits while game async loads true destination level.
      3. After the final destination finishes loading, player is teleported there smoothly again with black sphere enveloping him and camera.
    • Travel system works in conjuction with the save persistence system to bring player inventory to next level.
